## 3. Architecture

Modular monolith:

```
app/
  Domain/
    Shared/        Money, Quantity, NumberSequenceService, AuditLogger
    Locations/     LocationService (create/schedule/activate/deactivate, one-permanent rule), LocationContext, OperatingPeriodGuard, TerminalService
    Access/        user/role services, login event recorder
    Catalog/       PriceResolver, ProductService
    Pos/           CartPricer, CheckoutService (+ DTOs), IdempotencyGuard
    Orders/        OrderStatusMachine
    Payments/      CashTender, GcashTender
    Inventory/     InventoryLedger, StockReceiver, StockAdjuster
    Production/    RecipeResolver, ProductionPoster
    Cash/          ShiftService, ExpectedCashCalculator
    Refunds/       RefundService
    Reports/       report query objects
  Enums/           OrderStatus, PaymentStatus, OrderType, MovementType, ...
  Http/Controllers/{Admin,Pos,Staff}/   thin controllers
  Http/Requests/   Form Requests
  Policies/        per model; Gate::before only for nothing (no super-admin bypass except Owner role via permissions)
resources/js/
  layouts/  AdminLayout, PosLayout, StaffLayout
  pages/    admin/*, pos/*, staff/*
  components/ brand + shared UI
```

Principles: controllers validate (Form Request) → authorize (Policy/permission middleware) → call a Domain service → return Inertia response. Critical operations run in `DB::transaction` with explicit row locks. Vue holds only UI/cart-editing state; the server reprices everything.

## 6. Proposed Phase 1 scope (awaiting approval)

1. Scaffold Laravel 13 with the official Vue starter kit in a temp folder; merge into `Brevon POS/` without touching `docs/`, the SRS, or the prompt; `git init` with a sensible `.gitignore`.
2. Pin Composer platform PHP 8.4; `composer install` / `npm install`; record exact versions.
3. Create `brevon_pos` and `brevon_pos_test` databases; configure `.env` (local) and `phpunit.xml` (test DB); add `.env.example` with safe placeholders.
4. Add `EnsureSafeDatabase` guard for `migrate:fresh`, `migrate:reset`, `db:wipe`, `db:seed` against non-Brevon DB names or non-local env.
5. Config: `APP_TIMEZONE=UTC`, `config/brevon.php` (business timezone Asia/Manila, currency PHP, shift enforcement, negative stock).
6. Disable registration and passkeys (D-017, D-019); leave login working with the kit's default email login (username login comes in Phase 2).
7. Theme: Brevon tokens (per D-014 choice), fonts, logo; restyle auth pages; base `AdminLayout` with sidebar, `PosLayout` full-screen, `StaffLayout` — shells only, clearly marked "coming in Phase N".
8. Shared domain: `Money` value object + `Quantity` helpers with unit tests.
9. Tooling: Pint, Larastan (initial level 5), `types:check`, build; a `composer check` script running all gates.
10. README: setup, DB, run, test, build.
11. No location/customer work in Phase 1: the location model starts in Phase 2. Phase 1 adds nothing that conflicts with SRS v1.1 (no customer tables; no branch assumptions in the shells).
12. Gate: migrations on both DBs, `php artisan test`, Pint, Larastan, vue-tsc, `npm run build` — all green; update status docs; Phase 1 report.
